## P0: a core flow breaks or fails without telling the user
1. **Error messages are written but never shown.** Evidence: `LibraryModel.problem` (LibraryModel.swift:88) is set by launch failures (GameActions.swift:254), uninstall failures (:355), Starts With and rename (GameStartsWith.swift:52,77; GameReidentify.swift:86). `StoreCenter.problem` (StoreCenter.swift:85) is set by install/update/sign-in errors (:285), record saves (:426) and "runner can't start" (:477). `ConsoleCenter.problem` (ConsoleCenter.swift:18) is set when a BIOS or core is missing (ConsolePlay.swift:150,159,126). No view reads any of the three; a grep finds no reader outside Agent/.
   Impact: Play, Install or Uninstall does nothing and gives no reason, so the user is stuck. Fix: add one dismissable problem banner or alert in LibraryWindow that reads the three models, with "Show Log" or "Open Settings" when it applies.
2. **A failed store download disappears.** Evidence: `StoreCenter.activity` only returns running jobs (StoreCenter.swift:337), so a `.failed` job (:455-457) never shows in Activity, and its message goes to the unread `problem` field (item 1).
   Impact: an Epic/GOG/Amazon install that fails just vanishes. Fix: keep failed jobs in the activity list with their reason and Try Again / Dismiss.
3. **A Windows game that crashes or exits at once gives no notice and no log.** Evidence: `InstallCenter.watchSession` ignores the exit status (InstallCenter.swift:377). CrashLog keeps a backtrace (:379) but nothing tells the user. The panel only shows "Show Log" for store boot failures (GamePanel.swift:406-413).
   Impact: the user presses Play, sees nothing, and the button goes back to Play. Fix: when the exit is non-zero or the game ran under ~10 s, show "<Game> quit unexpectedly" with Show Log and Copy Summary, plus a notification if the app is hidden.
4. **Changing the games location hides installed games, and store games ignore it.** Evidence: the folder can only be changed through Run Setup Again. `applyStorage` writes `installs.location` (OnboardingModel.swift:591-602), but `LibraryModel.installsFolder` (LibraryModel.swift:98) and `InstallEngine.installs` (InstallEngine.swift:11) are read once at launch. `InstalledGames.all(in:)` scans a single folder (InstalledGame.swift:62), so games in the old folder drop out of the library after a relaunch. Store installs always go under Application Support (StoreCenter.swift:126).
   Impact: games seem lost, and large store games fill the internal disk. Fix: keep a list of known install roots and scan all of them, add a "Games Location" row in Settings > Library, and use the same root for store installs.
5. **The published Cartouche Wine still lacks SDL3, so controllers don't work in Windows games.** Evidence: runners.json:6-14 pins wine-crossover-26.3.0-1, whose SDL3 is missing (controller-wine-2026-10-21.md). 26.3.0-2 exists only in tests (RunnerUpdateTests.swift:49).
   Impact: no gamepad in any Windows game. Fix: publish 26.3.0-2 and bump runners.json and the signed remote manifest; RunnerUpdate then offers Update.
6. **These flows are merged but not proven live (release blockers, maintainer).** Steam owned-list export after Repair (route auth is still unclear, code-review-2026-10-21.md last section); D3DMetal on Silksong; direct-unpack and repack (direct-unpack/tasks.md, 6 open); Sparkle EdDSA key, signing cert and appcast (release-tasks-maintainer.md); first Mac build and test run of this branch.

## P1: features users expect from CrossOver, Whisky, Heroic, Mythic, Porting Kit or OpenEmu
7. **No per-game launch arguments or environment variables.** Evidence: GameSetup.swift:18-20 has only runner, graphics and translation; AdvancedGameOptions.swift:3-10 has fixed toggles only. Heroic, Mythic, Whisky and Kegworks all offer both. Fix: add `arguments` and `environment` to the setup, edit them in the panel's Advanced section, and use the allowlist in GameSetupResolver.isAllowed.
8. **No DLSS-via-MetalFX or ray tracing for D3DMetal.** Evidence: DLSS is only offered for DXMT with NV extensions (AdvancedGameOptions.swift:39-41), and the code has no `D3DM_ENABLE_METALFX` or `D3DM_SUPPORT_DXR`. CrossOver 26 has DLSS for D3DMetal and DXMT, and a DXR toggle. Fix: add options gated on D3DMetal 3.x being present.
9. **Prefix tools and the game log are not reachable from the game.** Evidence: winecfg, regedit, Run Program, Winetricks and Open Log exist only in Settings > Wine Prefixes (PrefixesView.swift:335-406). The game menu has none of them (GameActions.swift:75-180). Fix: add a "Wine Tools ▸" submenu and "Show Log" to the game menu and panel, using the same PrefixTools calls.
10. **No sort or filter, and imported Steam collections never appear.** Evidence: `games(in:)` has no sort order (LibraryModel.swift:220-227); SidebarItem is all / favorites / source (:4-8). `Game.collections` is filled (SteamLibraryImport.swift:102) but nothing in the UI reads it. The mockup has Recently Played (mockup/launcher.html). Fix: add sort options (Name, Recently Played, Playtime), an Installed-only filter, and Steam collections in the sidebar.
11. **Playtime is imported but not shown for PC games.** Evidence: `Game.playtimeMinutes` (Game.swift:69) is only read by the agent (AgentTools.swift:30); console games do show hours (ConsolePanelContent.swift). Fix: show total hours in the panel and card subtitle, and record time for installer and store games from session start and end.
12. **Store games don't say when an update is available.** Evidence: Check for Update just runs the update (GameActions.swift:126-129, StoreCenter.swift:360). There is no badge or scan. Heroic and Mythic show one. Fix: on refresh, ask the client for available updates (legendary/gogdl/nile list), then badge the card and offer Update.
13. **Store clients can't be updated without a new app.** Evidence: the client list is pinned inside the app only (StoreClients.swift:1,71), while runners.json has a signed remote manifest. If Epic's API changes, Epic stops working until the app updates. Fix: add a signed remote store-clients.json, the same way RunnerManifest.swift:159-165 does it.
14. **Cloud-save sync failures are only logged.** Evidence: StoreCenter.swift:521 and :575 write to AppLog only. Fix: show a non-blocking "Saves not synced, Try Again" on the panel.
15. **Steam games have no Stop button and are never shown as running.** Evidence: `running` only covers store and installer games (GameActions.swift:68). Fix: read the running app ID from SteamActivityReader and offer Stop through steam://.
16. **Smaller gaps.** No desktop/Dock shortcut for a game (Kegworks, Porting Kit and CrossOver have one). No per-game Wine debug channels (CrossOver has them). There are no community install recipes like Porting Kit's; the compat data covers part of that.
