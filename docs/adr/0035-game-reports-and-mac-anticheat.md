# 0035. Selected Mac reports and anti-cheat in Cartouche

Accepted, 2026-10-22, following the maintainer's UI review. Supersedes ADR 0009's user-facing anti-cheat wording.

The game details Mac picker uses reports for the selected model first, then averages comparable models within a GPU-strength ratio of 1.4. If no comparable report exists, it uses the nearest available model and identifies that fallback. It never scales reported FPS by GPU strength. Selecting another Mac can legitimately produce the same result when the relevant reports are identical; the app must not fabricate a change. Native and Wine play methods remain separate. The game panel follows the chosen Mac/Windows version, and the details sheet follows the same method.

The previous rule always expanded fewer than three comparable reports to the nearest five. On a game with two reports, that made every Mac display the same global average. The new rule preserves a sparse but relevant comparison instead. Reports without FPS keep their rating/settings, but contribute no invented FPS.

The details sheet links to `https://macgamingdb.app/games/<slug>`, using the slug returned by the API. Existing caches without the slug are refreshed when the game is opened. MacGamingDB reports remain local and are not redistributed.

Anti-cheat sections are titled Anti-Cheat. Known incompatible systems say “Anti-cheat is not compatible with Wine”; online modes requiring them are unavailable, while offline modes may work. Unknown compatibility stays unverified. An unknown VAC verdict remains unverified. The earlier blanket VAC rejection came from inherited README wording rather than a per-game check and was removed on maintainer review. Positive Proton reports never establish Cartouche support. The Wine-specific notice is hidden when the native Mac version is selected. The app does not show OS comparisons in this section.

A bundled [Heroic MacAnticheatData](https://github.com/Heroic-Games-Launcher/MacAnticheatData) snapshot provides Mac-specific status and anti-cheat names even while the separate compatibility release is unavailable. The snapshot was fetched on 2026-10-22 and keeps Steam app IDs, status and names. Its MIT license is bundled as `MacAnticheatData-LICENSE.txt`, and the UI credits the source. It is derived upstream from AreWeAntiCheatYet. This source deliberately differs from Proton support; [Valve's Proton integration documentation](https://partner.steamgames.com/doc/steamhardware/proton) describes platform-specific anti-cheat modules.

At the maintainer's request, the anti-cheat section also shows ProtonDB multiplayer counts and links directly to the game's ProtonDB reports. These are community observations of online play (which may include native builds), not proof that an anti-cheat works in Cartouche, and do not override known Wine incompatibility. Counts include their export date; absent multiplayer answers remain unavailable. The app ships 1,491 games with multiplayer answers from the official `reports_oct1_2026` export, aggregated over the preceding year. `tools/compat/build_protondb.py` regenerates `Resources/protondb-online.json` using the same parser as the nightly pipeline. The aggregate contains no report text or contributor information, is shared under ODbL 1.0, and remains available offline. A newer compatibility-feed entry supersedes its bundled counterpart.

The game panel shows storage on the same metadata line as its source and last play time. For installed Steam games, `SizeOnDisk` supplies measured installation bytes. Otherwise the app sums public base-game depots for the selected OS from the local appinfo cache and labels the result an approximation. Optional DLC and non-English language depots are excluded from that base-game estimate. This does not claim to be the compressed download size. No extra network request or Steam integration update is required for sizes.

GOG first sign-in also exposed a separate issue: gogdl 1.3.1 opens its auth-config file directly without creating its parent. Cartouche now creates that private directory before starting the client. The test client no longer creates it implicitly. Tokens retain the existing Keychain and temporary-file handling; an authentication failure still remains a failure.
