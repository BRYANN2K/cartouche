# Research: winegstreamer in the Cartouche Wine package (release 26.3.0-3)

Researched 2026-10-21. Phase: cartouche-wine 26.3.0-3. "(unverified)" means one secondary source, or my own inference.

## Question
What do we need to build and ship so that winegstreamer works in our relocatable x86_64 Wine 11 (CrossOver 26.3) package? That covers build and runtime needs, what others ship, licensing, Homebrew pitfalls, and a plan for the build.sh/bundle-deps.sh/package.sh/verify.sh scripts.

## Short answer
Don't take GStreamer from Homebrew. Its `gstreamer` formula is built with `-Dgpl=enabled` and links a GPL-3 FFmpeg plus x264 and x265. Instead, take the x86_64 slice of the official LGPL GStreamer.framework (built with cerbero, which is what Gcenx/WineHQ and Sikarugir ship). Copy a curated subset: core, base, a few good/bad/ugly plugins and gst-libav. Leave out openh264, x264 and x265. Set `GST_PLUGIN_SYSTEM_PATH` and `GST_REGISTRY` at runtime.

## Findings
### 1. What winegstreamer needs (Wine 11.0)
- Configure: pkg-config `gstreamer-1.0 gstreamer-video-1.0 gstreamer-audio-1.0 gstreamer-tag-1.0`, plus `gst/gst.h` and `gst_pad_new`. If these are missing, winegstreamer is silently not built ([configure.ac wine-11.0](https://raw.githubusercontent.com/wine-mirror/wine/wine-11.0/configure.ac)). We also need to drop `--without-gstreamer` from `build.sh` line 88.
- Elements created by name:
  - In `wg_parser.c` ([source](https://raw.githubusercontent.com/wine-mirror/wine/wine-11.0/dlls/winegstreamer/wg_parser.c)): `decodebin`, `videoconvert` and `audioconvert` from "base"; `deinterlace` and `videoflip` from "good".
  - In `wg_transform.c` ([source](https://raw.githubusercontent.com/wine-mirror/wine/wine-11.0/dlls/winegstreamer/wg_transform.c)): `capsfilter`, `audioresample`, `videoconvert` and `audioconvert`.
- Decoders and parsers are found at runtime by caps (`find_element(GST_ELEMENT_FACTORY_TYPE_DECODER/PARSER)`). The code special-cases `avdec_h264`, handles `wmvversion`/`wmaversion` caps, and its comments mention `avdec_wmav2` and `h264parse`. So WMV, VC-1 and WMA in practice need **gst-libav**: no LGPL-clean GStreamer plugin outside libav decodes them (inference, unverified).
- Init (`unixlib.c`, [source](https://raw.githubusercontent.com/wine-mirror/wine/wine-11.0/dlls/winegstreamer/unixlib.c)):
  - Calls `gst_init_check` with `--gst-disable-registry-fork`, so no helper process is spawned while scanning ([gst.c](https://raw.githubusercontent.com/GStreamer/gstreamer/main/subprojects/gstreamer/gst/gst.c)). This means `gst-plugin-scanner` is not needed for Wine (inference from code).
  - If the scanner is missing anyway, GStreamer falls back to scanning in-process ([gstregistry.c](https://raw.githubusercontent.com/GStreamer/gstreamer/main/subprojects/gstreamer/gst/gstregistry.c)).
  - A missing element prints `winegstreamer: failed to create %s, are %u-bit GStreamer "%s" plugins installed?`, which CI can grep for.
- Plugin search (gstregistry.c):
  - `GST_PLUGIN_SYSTEM_PATH_1_0` / `GST_PLUGIN_SYSTEM_PATH` replace the default paths. When either is set, `~/.local/share/gstreamer-1.0/plugins` is not scanned.
  - Otherwise the default is `<dir of libgstreamer>/gstreamer-1.0`, found through `dladdr` relocation, falling back to the compiled-in `PLUGINDIR`.
  - The registry cache is `GST_REGISTRY_1_0`, `GST_REGISTRY`, or `g_get_user_cache_dir()/gstreamer-1.0/registry.<cpu>.bin`.
  - Env semantics: [running.md](https://raw.githubusercontent.com/GStreamer/gstreamer/main/subprojects/gstreamer/docs/gst/running.md). The scanner lookup order (`GST_PLUGIN_SCANNER_1_0`, then relocated, then installed path) is in [gstpluginloader.c](https://raw.githubusercontent.com/GStreamer/gstreamer/main/subprojects/gstreamer/gst/gstpluginloader.c).
- Env a relocatable bundle should set:
  - `GST_PLUGIN_SYSTEM_PATH_1_0=<root>/lib/gstreamer-1.0`
  - `GST_PLUGIN_PATH_1_0=` (empty, so the user's Homebrew plugins are not picked up)
  - `GST_REGISTRY_1_0=<Cartouche support dir>/gst-registry-<build>.x86_64.bin`, so we never share a registry with a user's Homebrew GStreamer
  - optionally `GST_PLUGIN_SCANNER_1_0=<root>/libexec/gst-plugin-scanner` if we ship it
- macOS loader specifics:
  - Only a 64-bit GStreamer is needed. The macOS build is WoW64, so the unix side is x86_64 only. Inference from `--enable-archs=i386,x86_64` and macOS having no 32-bit support; not separately verified.
  - Plugins are `dlopen`ed. Their `@rpath/` dependencies resolve through the plugin's own `LC_RPATH`, not through libgstreamer's. So each plugin needs `-add_rpath @loader_path/..` (Apple dyld behaviour; unverified for GLib's `g_module_open` path).
- Wine 10 added an opt-in FFmpeg backend (`DisableGstByteStreamHandler=1`). In 11.0 GStreamer is still the default. The 11.0 notes add GStreamer-based dynamic format change, Indeo 5 and ASF Reader seeking ([10.0 ANNOUNCE](https://raw.githubusercontent.com/wine-mirror/wine/wine-10.0/ANNOUNCE.md), [11.0 ANNOUNCE](https://raw.githubusercontent.com/wine-mirror/wine/wine-11.0/ANNOUNCE.md)). Note that `build.sh` does not pass `--without-ffmpeg`.

### 2. How others ship it
- **Gcenx macOS_Wine_builds / WineHQ:**
  - The README lists runtime dependency `gstreamer-runtime` and configures `--with-gstreamer` ([repo](https://github.com/Gcenx/macOS_Wine_builds)).
  - In the macports-wine overlay ([Gcenx/macports-wine](https://github.com/Gcenx/macports-wine)), `gstreamer-runtime` installs the official `gstreamer-1.0-1.28.1-universal.pkg` into /Library/Frameworks. That pkg is 151,846,922 bytes, universal and complete ([Portfile](https://raw.githubusercontent.com/Gcenx/macports-wine/main/multimedia/gstreamer-runtime/Portfile)).
  - `gstreamer.framework` uses an x86_64-only tarball from [Sikarugir-App/gstreamer releases](https://github.com/Sikarugir-App/gstreamer/releases), latest 1.28.1, dated 02 Mar, no year shown, probably 2026 ([Portfile](https://raw.githubusercontent.com/Gcenx/macports-wine/main/multimedia/gstreamer.framework/Portfile)).
  - The plugin selection in those tarballs is not documented.
- **Sikarugir/Kegworks:** uses the same Sikarugir-built x86_64 GStreamer.framework (inferred from the org name; contents unverified).
- **Whisky fork (frankea):** the v4.0.0-beta.2 notes say it bundles "GStreamer 1.26.3, 231 plugins", resolves the plugin path relative to the runtime, and adds FFmpeg for winedmo. This is a pre-release, seen only via a newreleases.io mirror ([link](https://newreleases.io/project/github/frankea/Whisky/release/v4.0.0-beta.2)). Not confirmed.
- **CrossOver:**
  - On Linux it relies on the distro's GStreamer and has a `cxfix missinggstreamer1libav` fix ([CodeWeavers KB](https://support.codeweavers.com/missinggstreamer1libav)).
  - What the Mac app bundles is not confirmed; codeweavers.com did not resolve from here.
- **Proton 10** ([Makefile.in](https://raw.githubusercontent.com/ValveSoftware/Proton/proton_10.0/Makefile.in)):
  - Builds core with `tools=disabled`.
  - gst-plugins-base with `auto_features=disabled`, enabling app, audioconvert, audioresample, playback, typefind, videoconvertscale, ogg, opus, theora, vorbis and others.
  - gst-plugins-good: audioparsers, avi, deinterlace, isomp4, matroska, mpg123, videofilter, vpx, wavparse, id3demux and others.
  - gst-plugins-bad: only videoparsers, hls and mpegtsdemux.
  - gst-libav, plus rs dav1d.
  - No ugly, x264 or openh264. FFmpeg is built with `--disable-everything --enable-demuxer=matroska` only to compile gst-libav: "we don't ship it". The runtime libavcodec comes from the Steam Runtime (inference).

### 3. Licensing and patents (not legal advice)
- GStreamer core, base, good, bad and ugly, and gst-libav are LGPL. GPL obligations only appear when GPL plugins or a GPL FFmpeg are linked ([legal FAQ](https://raw.githubusercontent.com/GStreamer/gstreamer/main/subprojects/gst-docs/markdown/frequently-asked-questions/legal.md)).
- **Homebrew is the problem:**
  - The `gstreamer` 1.28.8 formula is a single monolithic build: `-Dlibav/-Dugly/-Dbad/-Dgpl/-Drs=enabled`, depending on ffmpeg, x264, x265, gtk4, python and others ([gstreamer.rb](https://raw.githubusercontent.com/Homebrew/homebrew-core/master/Formula/g/gstreamer.rb), fetched 2026-10-21).
  - Homebrew `ffmpeg` 9.0.2 is `GPL-3.0-or-later` with `--enable-gpl --enable-version3 --enable-libx264 --enable-libx265` ([ffmpeg.rb](https://raw.githubusercontent.com/Homebrew/homebrew-core/master/Formula/f/ffmpeg.rb)).
  - Copying its libgstlibav would turn the package GPL-3, and it ships x264 and x265 encoders we don't need.
- **Cerbero (official framework):**
  - FFmpeg is `LGPLv2_1Plus` with `nonfree` and `version3` disabled ([ffmpeg.recipe](https://raw.githubusercontent.com/GStreamer/cerbero/main/recipes/ffmpeg.recipe)).
  - openh264 is built from source, BSD-2 ([openh264.recipe](https://raw.githubusercontent.com/GStreamer/cerbero/main/recipes/openh264.recipe)), and enabled in bad ([recipe](https://raw.githubusercontent.com/GStreamer/cerbero/main/recipes/gst-plugins-bad-1.0.recipe)).
- **openh264:**
  - Cisco's MPEG LA coverage applies only to Cisco's own binary, downloaded separately onto the user's machine. A source-built openh264 has no patent licence. Sources: [Mozilla 2013](https://blog.mozilla.org/press/2013/10/video-interoperability-on-the-web-gets-a-boost-from-ciscos-h-264-codec/), [Linphone wiki 2022](https://wiki.linphone.org/xwiki/wiki/public/view/Lib/Features/Codec%20H264%20on%20Android/). Both are older than 12 months, and openh264.org was unreachable, so not confirmed against the current BINARY_LICENSE.
  - It is also redundant here, because Wine prefers `avdec_h264`. Leave it out.
- **Patents:** H.264, AAC, WMV/VC-1 and WMA decoders in LGPL FFmpeg carry the same patent exposure every FOSS distribution accepts (Wine-on-mac builds, VLC, and so on). That is unverified for any specific jurisdiction. Cartouche is free and non-commercial, but that is not a patent defence.
- **Recommended set (safest that still covers most cutscenes):**
  - core, plus base (app, playback/decodebin, typefind, audioconvert, audioresample, videoconvertscale, pbtypes, ogg/vorbis/theora optional)
  - good: isomp4, matroska, avi, wavparse, audioparsers, deinterlace, videofilter (videoflip), id3demux, mpg123
  - bad: videoparsersbad (h264parse/vc1parse), mpegpsdemux, mpegtsdemux
  - ugly: asf (asfdemux, LGPL)
  - gst-libav linked to LGPL FFmpeg
  - Exclude: openh264, x264, x265, faad, a52dec, dts, and every `codecs_gpl`/`restricted` plugin. Bink is not GStreamer's job.

### 4. Homebrew x86_64 pitfalls
- Homebrew moved Intel macOS to Tier 3 in Sept 2026 (no new x86_64 bottles) and plans full removal on 2027-09-01. Seen only in secondary reports ([borncity](https://borncity.com/news/homebrew-7-0-0-paketmanager-beendet-intel-support-ab-2027/), [openrobotics](https://discourse.openrobotics.org/t/homebrew-dropping-support-for-macos-intel-amd64/57731)); not confirmed, because brew.sh was unreachable. Either way, a source build of `gstreamer` (rust, gtk4, ffmpeg tree) on CI would take hours.
- Homebrew plugin binaries hard-code `/usr/local/...` paths. `bundle-deps.sh` already rewrites these to `@rpath`, but it adds no `LC_RPATH` to plugins. libgstreamer's compiled `PLUGINDIR` and the scanner path still point into /usr/local unless the env vars above are set.
- GLib/GIO:
  - GStreamer core does not need GIO modules. Set `GIO_MODULE_DIR` to an empty bundle dir (or leave it) so that a user's `/usr/local/lib/gio/modules` with a mismatched GLib is never loaded. This is inference; I found no source.
  - Cerbero 1.22.2 once shipped libavcodec linked to Homebrew's `/usr/local/opt/xz` ([cerbero#428](https://gitlab.freedesktop.org/gstreamer/cerbero/-/issues/428)). That is why `check-deps.sh` must also scan plugins.
  - The framework install names are `@rpath`-relative since the relocatable-prefix change ([cerbero MR 929](https://gitlab.freedesktop.org/gstreamer/cerbero/-/merge_requests/929)).

### 5. Build and package plan
- **pins.env:** add `GST_VERSION=1.28.x` and the URLs and sha256 for `gstreamer-1.0-$V-universal.pkg` and `gstreamer-1.0-devel-$V-universal.pkg` from gstreamer.freedesktop.org/data/pkg/osx/ (the path used by Gcenx). Alternatively, pin the Sikarugir x86_64 tarball.
- **fetch.sh:** download both pkgs and check their hashes.
- **build.sh:**
  1. Run `pkgutil --expand-full` on the pkgs into `$work/gst`. Do not use `installer`, so nothing lands in /Library.
  2. Run `lipo -thin x86_64`.
  3. Point `PKG_CONFIG_PATH` at its `lib/pkgconfig`, with the `prefix=` rewritten.
  4. Copy `libgstreamer/base/video/audio/tag/pbutils/app` plus their GLib deps into `$deps/lib` via `bundle-deps.sh`.
  5. Replace `--without-gstreamer` with `--with-gstreamer`, and fail if `dlls/winegstreamer` was not built (check for `lib/wine/x86_64-unix/winegstreamer.so`).
- **bundle-deps.sh:**
  - Add a mode for plugins: copy the curated `lib/gstreamer-1.0/libgst*.dylib` list into `$deps/lib/gstreamer-1.0/`.
  - Run `install_name_tool -add_rpath @loader_path/..` on each plugin, queue their dependencies (libav*, liborc, …) into `lib/`, then `codesign -s -`.
  - Optionally ship `libexec/gstreamer-1.0/gst-plugin-scanner` with `-add_rpath @executable_path/../../lib`.
- **package.sh:**
  - Add the GStreamer and FFmpeg LGPL notices and a SOURCE.md section with the source URLs for GStreamer $V and the cerbero FFmpeg tarball, as LGPL requires.
  - Record `GST_VERSION` in BUILDINFO.
  - The size impact is unmeasured. Estimate: a few tens of MB uncompressed for the subset, versus 152 MB for the full universal pkg (unverified).
- **App run script:** export `GST_PLUGIN_SYSTEM_PATH_1_0`, an empty `GST_PLUGIN_PATH_1_0`, and `GST_REGISTRY_1_0` (see section 1).
- **verify.sh (headless):**
  1. Run `check-deps.sh` over `lib/gstreamer-1.0` too: no `/usr/local`, `/opt/homebrew` or `/Library/Frameworks` references.
  2. Probe with the framework's `gst-inspect-1.0` (not shipped), pointed only at our dir: `env -i GST_PLUGIN_SYSTEM_PATH_1_0=$root/lib/gstreamer-1.0 GST_REGISTRY_1_0=$tmp/reg.bin gst-inspect-1.0 --exists <el>` for decodebin, videoconvert, audioconvert, audioresample, capsfilter, deinterlace, videoflip, avdec_h264, avdec_wmv3, avdec_vc1, avdec_wmav2, avdec_aac, h264parse, qtdemux, asfdemux. This probe loads the framework's libgstreamer, not our copy, so it only checks the plugins.
  3. End-to-end: a tiny mingw-built Media Foundation probe (`MFCreateSourceReaderFromURL` + `ReadSample` to the first decoded RGB32/NV12 frame) run on a 1-second H.264 MP4 and a WMV9 file committed as fixtures. Run it with `WINEDEBUG=+mfplat` and fail if stderr contains `winegstreamer: failed to create`. No display is needed for a source reader (unverified, needs a CI trial).

## Open points
- I could not inspect the actual contents (plugin list, sizes) of the official 1.28 pkg or of the Sikarugir x86_64 tarball, nor what CrossOver.app ships for Mac.
- Unconfirmed: that `dladdr` relocation is active in official framework builds without env vars. Set the env vars regardless.
- Not tested: whether the MF probe runs headless on a GitHub macOS-15 x86_64 runner.
- The Homebrew Intel Tier 3 dates come only from secondary sources.
- Legal review of the H.264/AAC/WMV patent risk is outside the scope of this research.
