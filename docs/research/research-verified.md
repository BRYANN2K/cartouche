Scope: technical identification and implementation feasibility only. “Confirmed” means supported by cited documentation; heuristic or version-dependent statements are explicitly qualified. No installer execution or copyrighted payload links are included.

## Corrected decision tree

1. **Static inspection only:** inventory filenames, sizes, magic, PE structure/overlay, archive parser results, sidecars and volume families. Never execute to classify. Filename/brand/`.bin` alone is weak evidence.
2. **Existing game directory (strong evidence):** check executable plus matching Unity `_Data`, Unreal layout/package markers, and launcher metadata such as Steam `appmanifest` or Epic `.egstore`. Report evidence and confidence; these markers can be copied or stale.
3. **Inno candidate:** use `innoextract --data-version`/`--info` and `--list` in non-writing mode; record the tool's supported range. If version unknown/newer, classify as “Inno-like/unsupported,” not generic archive. Do not infer optional choices from filename lists.
4. **Inno plus runtime decompressor:** helper names (`ISDone.dll`, `unarc.dll`, `CLS-*.dll`), script/import references, config and FreeArc magic are corroborating evidence. Classify as installer requiring runtime behavior; innoextract alone may not reproduce installation/decompression. Unknown helper license/API remains unknown.
5. **Other installer:** validate NSIS structure; inspect InstallShield clues as a set; parse MSI database; vendor/InstallAware strings remain weak evidence absent a parser. Offer guided Wine install, never silent execution.
6. **Archive/SFX:** validate with archive parser and full part set; recognize 7-Zip SFX markers with appended archive structure. Treat generic executable+archive as SFX/ambiguous until supported evidence establishes more.
7. **Portable game/archive:** if extracted contents match installed-game structure, classify portable build. Do not run redistributables automatically.
8. **Ambiguous or conflicting:** present observed facts/confidence and ask the user. Missing volume blocks extraction; optionality requires script/manifest evidence. Never default an unknown EXE to installer execution.

## Ranked speed plan (verified scope and license posture)

1. **Measure first, tune exact matched helpers/configs.** Record per-worker CPU, effective threads, RSS, disk/temp I/O, swap and output hashes. Change one codec-documented parameter at a time. `MaxThreadsUsage`/`MaxMemoryUsage` are not universal; SREP `-mem` is a memory/stability control, not guaranteed speedup. No new license burden; preserve bundled notices.
2. **Reduce memory pressure only if measured.** Measure SREP VM/temp activity and swap before changing temp location or imposing limits. RAM disk may hurt by stealing decoder memory. SREP source is available but exact license unconfirmed: do not bundle until rights cleared.
3. **Native open-codec experiments, narrowly dispatched.** FreeArc sources exist (GPLv2 listing; inspect exact tree/dependencies); SREP source license unresolved; XTool is MIT but archived/Windows-oriented. Test bitstream parity, plugin dependency and build feasibility per exact version. FreeArc Mac CLI prior art does not establish native unarc/CLS support.
4. **Keep closed/unclear codecs in authorized runtime.** LOLZ/Magic2 status and redistribution rights are unclear; Oodle is proprietary and contract-controlled. Use only authorized matching runtime; no replacement/reimplementation assumption.
5. **Do not parallelize dependent solid blocks.** Only parallelize proven independent volumes/files, and verify hashes. No credible controlled Wine/Linux benchmark establishes a universal best setting.
6. **Ignore marginal startup/I/O tricks until traces support them.** Warm starts, temp filesystem, caching and Wine sync flags require platform/build-specific measurement; no guaranteed gain follows from Linux advice.

License clearance before distribution: innoextract zlib/libpng; FreeArc listed GPLv2 (verify dependencies); SREP unresolved; XTool MIT; LOLZ/Magic2 unresolved; Oodle proprietary/contractual. No codec is cleared merely because a binary is available.
